Graphics & mslgd

Running OpenGL apps

How 3D apps render here, which path suits which app, and what to do when one refuses to start.

OpenGL apps work. There are two ways they can render, and which is better depends on the app.

The two paths#

PathOpenGL versionGood for
CPU (the default)4.5Anything, including apps needing newer OpenGL. Slower for heavy 3D.
GPU (opt in)4.1Apps that stay at 4.1 or below and want the speed.

The CPU path is software rendering — correct, complete, and slow in proportion to how much the app draws. The GPU path sends OpenGL to your Mac's real graphics hardware, and is capped at OpenGL 4.1 by the Mac side of it.

warning

Newer than 4.1 will not run on the GPU

This is the single most useful thing to know here. Blender wants OpenGL 4.3: on the GPU it reports unsupported hardware and will not start properly, and on the CPU it runs. If a 3D app refuses to start only when GPU acceleration is on, this is why.

Turning the GPU path on at all is GPU acceleration for OpenGL in Experimental Features. Individual apps can override it from their right-click menu, which is how you keep one app on the CPU while everything else uses the GPU.

Checking what an app is getting#

From a terminal in the instance:

A renderer naming llvmpipe is the CPU path. Anything else is the GPU path. glxgears is the quickest way to see whether GL works at all.

If glxinfo is missing, install mesa-utils.

When an app will not start#

It saysTry
Unsupported hardware, or needs OpenGL 4.2 or newerPut that app on the CPU
Cannot open displayCheck the Graphics gate on the Sandbox tab
Nothing, and exits immediatelyLaunch it from a terminal to see its own message
Lost connection to rendering serverThe GPU renderer is not reachable; use the CPU

Launching from a terminal in the instance is worth doing early. A Linux app that fails on startup almost always says why, and that message never reaches the Mac side.
