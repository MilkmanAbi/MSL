Environment tricks for stubborn apps

The handful of variables that rescue an app which will not render, scale or start.

Most apps need none of this. When one misbehaves, these are the levers, and they are the same ones you would use on any Linux machine with software rendering.

The useful ones#

VariableWhat it doesReach for it when
LIBGL_ALWAYS_SOFTWARE=1Forces Mesa's software rendererAn app renders wrongly on the GPU path
GALLIUM_DRIVER=llvmpipePicks the software driver outrightThe same, more firmly
GSK_RENDERER=cairoGTK4 draws without OpenGLA GTK4 app shows a blank or black window
QT_QUICK_BACKEND=softwareQt Quick draws without OpenGLA Qt app's interface is blank or garbled
SDL_VIDEODRIVER=x11Stops SDL choosing WaylandAn SDL game exits saying it cannot find a display
SDL_RENDER_DRIVER=softwareSDL draws without GLAn SDL game opens a window and draws nothing
GDK_BACKEND=x11Stops GTK choosing WaylandA GTK app cannot find a display
QT_QPA_PLATFORM=xcbThe same for QtA Qt app cannot find a display

MSL already sets the first few of these for apps it launches, so an app started from the Applications tab usually has sensible values. These are for when you are running something by hand, or an app needs something unusual.

Older games and LOVE apps#

Older games, and anything built on an old LOVE (love2d) runtime, are the most common thing to need help. They tend to ask for an OpenGL setup that assumes a real graphics card and give up quietly when they do not get it.

In rough order of what to try:

  1. Run it from a terminal, so you can see what it actually says.
  2. SDL_VIDEODRIVER=x11 — many exit immediately without this because they try Wayland first.
  3. LIBGL_ALWAYS_SOFTWARE=1 — on the CPU path, where OpenGL 4.5 is available.
  4. SDL_RENDER_DRIVER=software if it opens a window but draws nothing.
  5. If it is packaged as a Flatpak or Snap, try the plain distribution package instead: sandboxed packages bring their own graphics libraries, which is one more thing between the app and mslgd.
note

Flatpaks and Snaps are a different environment

A sandboxed app cannot see /tmp the way an ordinary one can, and brings its own copy of Mesa. When an app works as a distribution package and not as a Flatpak, that difference is usually why — it is not a fault in either.
