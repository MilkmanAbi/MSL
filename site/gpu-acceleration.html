Experimental Features

GPU acceleration for OpenGL

Running Linux OpenGL on the Mac's real GPU, and the version ceiling that decides whether you want to.

Off by default. With it on, Linux OpenGL is rendered on your Mac's real GPU through Metal instead of on the CPU.

The ceiling, which is the whole decision#

warning

The GPU path stops at OpenGL 4.1

The Mac side goes through Apple's OpenGL, which caps at 4.1. The CPU path — the default — offers 4.5. So anything that needs newer than 4.1 will not run on the GPU at all, while it runs fine on the CPU.

Blender is the usual example: it wants 4.3 and reports unsupported hardware on the GPU, while working on the CPU.

Good on the GPUBetter on the CPU
Chromium's GL, many games, older CADBlender and anything else needing OpenGL 4.2 or newer
Anything that stays at OpenGL 4.1 or belowAnything that renders incorrectly on the GPU

It needs a piece that is installed separately#

The GPU path needs a renderer on the Mac side. Without it this switch does nothing at all and apps stay on the CPU — quietly, which is the right failure: you get working software rather than a broken window.

Per-app, not just global#

This switch is the default for every app, but each app can be set on its own from its right-click menu in the Applications tab — see The app right-click menu. An app pinned to the CPU stays there whatever this switch says, which is how you keep Blender working while everything else uses the GPU.

Takes effect after the instance restarts.
